# Аналіз та обробка зображень космічних апаратів

Індивідуальний STEM-проєкт (Варіант 1): ручна реалізація п'яти класичних методів
комп'ютерної графіки та їх порівняння за метриками якості на вибірці з 30 зображень
космічних апаратів (супутники, космічні станції, ракети-носії, марсоходи).

Усі алгоритми обробки та метрики реалізовані вручну на Python + NumPy.
OpenCV використовується **лише** для декодування/кодування файлів зображень
(`cv2.imdecode`, `cv2.imencode`), matplotlib — лише для побудови графіка метрик.

## Методи

| № | Метод | Категорія | Файл | Призначення |
|---|-------|-----------|------|-------------|
| 1 | Фільтр Гауса | Фільтрація | `src/filters.py` | Зниження шуму на знімках |
| 2 | Оператор Собеля | Контурний аналіз | `src/filters.py` | Виділення меж корпусів, панелей, ферм |
| 3 | Гістограмне вирівнювання (CDF) | Гістограмна корекція | `src/adjustments.py` | Підвищення контрасту темних кадрів |
| 4 | Морфологічна ерозія | Морфологічна обробка | `src/adjustments.py` | Прибирання дрібних яскравих артефактів (зірки, «гарячі» пікселі) |
| 5 | Статистичні характеристики | Обчислення статистик | `src/metrics.py` | Середня інтенсивність, дисперсія, контраст (СКВ), ентропія |

Метрики якості (`src/metrics.py`): **MSE**, **PSNR**, **SSIM** (гаусове вікно 11×11, σ = 1.5,
за Wang et al., 2004).

### Коротко про алгоритми

- **Згортка** (`convolve2d`): цикл по елементах ядра; для кожного зсуву додається
  зсунутий фрагмент доповненого (дзеркально) зображення, помножений на коефіцієнт ядра.
- **Сепарабельна згортка** (`convolve_separable`): для ядер виду `K = k·kᵀ` — два 1D-проходи
  (по рядках, потім по стовпцях).
- **Гаус**: ядро `G(x,y) = exp(-(x²+y²)/(2σ²)) = g(x)·g(y)`, нормоване на суму;
  застосовується сепарабельно.
- **Собель**: `Gx`, `Gy` ядрами 3×3, модуль `√(Gx²+Gy²)`, нормування до [0, 255],
  опційно бінаризація за порогом.
- **Гістограмне вирівнювання**: `h(v) = round((CDF(v) − CDF_min) / (N − CDF_min) · 255)`.
- **Ерозія**: мінімум у квадратному вікні `k×k` (для бінарних зображень — класична ерозія).
- **SSIM**: `((2μxμy + C1)(2σxy + C2)) / ((μx² + μy² + C1)(σx² + σy² + C2))`, усереднення карти.

### Оптимізація: сепарабельна згортка

Гаусове ядро розкладається на добуток двох одновимірних: `G(x,y) = g(x)·g(y)`. Тому 2D-згортку
`n×n` замінено двома 1D-проходами, і кількість множень на піксель падає з `n²` до `2n`.
Найбільше це прискорює SSIM: там 5 усереднень вікном 11×11 на кожне порівняння (121 → 22 множення).

| Замір (кадр 1280×960) | До | Після | Прискорення |
|---|---|---|---|
| Один SSIM | 1.16 с | 0.24 с | ×4.8 |
| Фільтр Гауса 5×5 | 0.059 с | 0.023 с | ×2.6 |
| Повний прогін 30 кадрів, 5 методів | 149 с | 41 с | ×3.6 |

Результат ідентичний 2D-згортці: розмиті зображення збігаються піксель у піксель, різниця SSIM
≈ 2·10⁻¹⁶ (похибка float64). Еквівалентність перевіряє тест `test_separable_matches_2d_convolution`.
Оператор Собеля (ядро 3×3) лишається на звичайній `convolve2d`.

### Сценарій перевірки (критерій C1)

Для оцінювання шумоподавлення до кожного зображення додається синтетичний гаусів шум
(σ = 20, фіксований `random_seed`). Фільтр Гауса застосовується до зашумленої копії, а
метрики рахуються відносно чистого оригіналу. У CSV поруч зберігається
`mse_noisy_baseline` — MSE зашумленого входу. Успіх: `mse < mse_noisy_baseline`.
Решта методів застосовується до оригіналу; їх SSIM показує ступінь трансформації.

```
space_image_project/

│                            #   sobel_binary/, histogram_equalization/, erosion/

│   ├── __init__.py
│   ├── filters.py           # згортка (2D і сепарабельна), Гаус, Собель
│   ├── adjustments.py       # гістограма, CDF, вирівнювання, ерозія
│   ├── metrics.py           # статистики, MSE, PSNR, SSIM
│   └── utils.py             # конфіг, I/O, перетворення в сірий, шум

├── tests/test_methods.py    # unit-тести на масивах 3×3
├── reports/                 # metrics_results.csv, metrics_summary.csv/.png
├── main.py                  # головний скрипт
├── requirements.txt
├── .pylintrc
├── README.md
└── META-USAGE
```

## Встановлення

Потрібен Python 3.9+.

```bash
git clone https://github.com/yaroslavronenko-ux/space_image_project.git
cd space_image_project
python -m venv .venv
# Windows:
.venv\Scripts\activate
# Linux/macOS:
source .venv/bin/activate
pip install -r requirements.txt
```

## Запуск

1. Покладіть зображення у `data/raw/` (підтримуються `.jpg .jpeg .png .bmp .tif .tiff`).
2. Запустіть усі методи:

```bash
python main.py
```

Вибір окремих методів:

```bash
python main.py --method gaussian sobel
python main.py --method histogram_equalization erosion statistics
```

Інші аргументи (мають пріоритет над конфігом):

```bash
python main.py --config configs/config.json --input data/raw --output data/processed --report reports/metrics_results.csv
```

## Налаштування (`configs/config.json`)

| Ключ | Значення за замовч. | Опис |
|------|------|------|
| `random_seed` | 42 | seed генератора шуму (відтворюваність) |
| `noise.enabled`, `noise.sigma` | true, 20.0 | синтетичний гаусів шум для перевірки Гауса |
| `gaussian.kernel_size`, `gaussian.sigma` | 5, 1.2 | розмір ядра (непарний) і σ |
| `sobel.threshold` | 60 | поріг бінарної карти контурів (0–255) |
| `sobel.save_binary` | true | чи зберігати бінарну карту |
| `histogram_equalization.levels` | 256 | кількість рівнів яскравості |
| `erosion.kernel_size`, `erosion.iterations` | 3, 1 | розмір структурного елемента, кількість ітерацій |
| `statistics.entropy_bins` | 256 | кількість бінів для ентропії |
| `ssim.*` | 11, 1.5, 0.01, 0.03 | вікно, σ вікна, K1, K2 |
| `methods` | усі 5 | методи за замовчуванням |

Параметри змінюються лише в конфігу, без правок коду.

## Результати

- `reports/metrics_results.csv` — рядок на кожну пару «зображення × метод»: `time_ms`,
  `mse`, `psnr`, `ssim`, `mse_noisy_baseline`, `mean`, `variance`, `contrast`, `entropy`.
- `reports/metrics_summary.csv` — середні значення по кожному методу.
- `reports/metrics_summary.png` — діаграма середніх PSNR та SSIM.
- `data/processed/<метод>/` — оброблені зображення.

## Обробка крайніх випадків

Порожні, пошкоджені та непідтримувані файли, а також зображення, менші за 3×3, пропускаються
з попередженням у консолі — програма не завершується аварійно. Кольорові (BGR), RGBA,
16-бітні та однотонні зображення приводяться до 8-бітного сірого вручну. Шляхи з кирилицею
підтримуються.
